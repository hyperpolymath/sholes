= Dev Container Usage
:author: {{AUTHOR}} <{{AUTHOR_EMAIL}}>

== Overview

The image (`Containerfile`) is `cgr.dev/chainguard/wolfi-base` with bash, curl,
git, just, openssh-client and a C toolchain from Wolfi packages, plus the Nickel
release binary (SHA-256 checked). It uses no dev container *features*: the
feature images are pulled from ghcr.io and can fail anonymously, which would stop
anyone from opening the container.

You work as `nonroot`, the user built into wolfi-base (uid/gid 65532).

There are two configurations for the same image:

[cols="1,2,3"]
|===
| Config | Engine | Why

| `devcontainer.json`
| rootless Podman (estate default)
| Maps your host user onto `nonroot` with `--userns=keep-id:uid=65532,gid=65532`,
  so the bind-mounted workspace is writable. `--security-opt=label=disable`
  lets the mount work on SELinux-enforcing hosts.

| `docker/devcontainer.json`
| Docker, GitHub Codespaces, Gitpod
| Docker rejects `--userns=keep-id`, so this one has no `runArgs`.
|===

== VS Code (local, Podman)

. Install the *Dev Containers* extension (`ms-vscode-remote.remote-containers`).
. Set `dev.containers.dockerPath` to `podman` in VS Code settings.
. Open the repo folder, then choose **Reopen in Container** and pick
  **{{PROJECT_NAME}} (Podman)**.

== devcontainer CLI (Podman)

[source,sh]
----
bunx @devcontainers/cli up --workspace-folder . --docker-path podman
----

== GitHub Codespaces

. From the repository on GitHub, click **Code > Codespaces > ... > New with options**.
. Choose the **{{PROJECT_NAME}} (Docker / Codespaces)** configuration.

== Gitpod

. Prefix the repo URL with `https://gitpod.io/#` to launch a workspace.
. Point Gitpod at `.devcontainer/docker/devcontainer.json`.

== Customization

Replace the `{{PROJECT_NAME}}` placeholders in both `devcontainer.json` files and
the `Containerfile` with your actual project name. `just deps` runs automatically
after the container is created. Run it again to check the environment.
