= SHOLES — Engineering Receipt
:toc:

This file records the implementation boundary behind the project README. It
separates finite-list proof claims, runtime contracts, and operating-system
integration instead of presenting one as another.

== Quotient projection

The mathematical source model is `Byte = Fin 256` and `Stream = List Byte` in
`proofs/agda/Sholes/Core.agda`. Text line spellings are projected as follows:

[source,text]
----
canon(CRLF) = LF
canon(CR)   = LF
canon(LF)   = LF
canon(binary) = binary
----

The Agda source and Lean/Coq transcriptions expose idempotence, quotient
invariance, parametric hash coherence, binary preservation, and POSIX/Windows
lens laws. The relation is equality of canonical line-token sequences. The
cryptographic theorem is parametric in `H`; it does not assert collision
resistance for SHA-1, SHA-256, BLAKE3, or any other hash.

== Classifier and non-interference

`crates/sholes-core/src/classifier.rs` checks NUL in a bounded 8192-byte header
and validates complete slices as UTF-8. Malformed UTF-8 is a conservative
binary result. Binary bytes are copied without entering the line-ending state
machine. This is stronger than a file-extension heuristic and is intentionally
not a promise that every printable binary format can be inferred from bytes.

== Streaming runtime

`StreamingCodec` in `crates/sholes-core/src/normalize.rs` stores no heap data:

* a classification;
* one pending CR; and
* two pending bytes for a Windows CRLF output.

`push` reports consumed and produced counts so a caller can retry with ring
buffers. `finish` emits a final lone CR exactly once. The complete-slice API
calculates exact capacity and drives the same state machine; it is a convenience
wrapper, not a separate algorithm.

`ProjectedFile` is a FUSE/9P/WebDAV-neutral read callback adapter. It implements
allocation-free projected `read_at` semantics; a platform adapter remains
responsible for mounting, permissions, invalidation, and syscall scheduling.

== Creusot boundary

`crates/sholes-core/src/contracts.rs` is the verifier ledger. It names the
`valid_buffer`, `is_binary`, `is_text`, and `is_canonical_lf` predicates and
records the equivalent Creusot `requires`/`ensures` surface. Ordinary `rustc`
sees comments only, so the default workspace has no verifier/runtime dependency.
The Why3/Coq proof boundary covers the local transducer and buffer obligations,
not filesystem or kernel behaviour.

== Git process filter

`crates/sholes-cli/src/packet_line.rs` frames arbitrary bytes as Git pkt-lines.
`filter-process` performs the protocol v2 handshake, advertises clean and
smudge, reads flush-delimited content, and returns status plus transformed
content. `clean`, `smudge`, and `audit` are also available as standalone
commands. `init --global` writes the four Git filter configuration keys.

== Testing

The checked-in Rust tests cover line-ending permutations, idempotence, malformed
UTF-8 and NUL preservation, CRLF chunk boundaries, output backpressure,
projected random reads, deterministic generated inputs, and pkt-line binary
framing. `crates/sholes-core/fuzz/` contains an optional `cargo-fuzz` target.
`verification/fuzzing/differential.sh` compares a built `sholes clean` binary
with GNU `dos2unix` when both are explicitly installed; the external utility is
not treated as a proof oracle.

== Receipts and limits

[source,text]
----
Rust runtime:             crates/sholes-core + crates/sholes-cli
Formal source:            proofs/agda/Sholes/
Cross-prover copies:      proofs/lean/Sholes/, proofs/coq/Sholes_Core.v
Creusot contract ledger:  crates/sholes-core/src/contracts.rs
Protocol tests:           crates/sholes-cli/src/packet_line.rs
Status ledger:            docs/status/PROOF-STATUS.adoc
----

The repository currently has no Rust/prover binaries installed in the minimal
agent environment. Commands that require them fail closed; this receipt does
not turn an unavailable toolchain into a proof result.
