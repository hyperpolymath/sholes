= LLM warm-up — rsr-template-repo (maintainer)

Paste this into an AI assistant before release, CI or governance work on
rsr-template-repo. Read `llm-warmup-dev.adoc` first; this adds what a maintainer owns.

== The provisioning set

This repository is provisioned from the estate canon
(https://github.com/hyperpolymath/standards, `3-practice/provisioning/`).
Repo-specific facts live in `.machine_readable/descriptiles/provisioning_praxis.deed`.
`provision-set realign` overwrites only the engine: `launcher.sh`,
`build/just/provision*.{just,sh}` and `channels.scm`; change behaviour through the
deed, never by hand-editing those. Everything else (`guix.scm` once real,
`manifest.scm`, `mise.toml`, the Justfile, `docs/` and these warm-ups) is minted
once and then belongs to this repository: keep it true as the code changes.

== Keeping it current

* `just toolchain-refresh` — `mise up --bump`, `mise lock`, re-pin `channels.scm`.
  Commit the lock changes on their own.
* `just doctor` must be clean before a release; WARN codes are tracked, not ignored.
* The `provisioning-check` workflow reports drift from the canon.

== Release

A release is a signed tag `v<semver>` on `main`; pushing it runs `.github/workflows/release.yml`, which builds the release notes, publishes the GitHub release (`softprops/action-gh-release`) and attests build provenance. Bump `version` in the Justfile and `CITATION.cff` first, in the same PR. This repository is a GitHub *template*: a release changes what every new repository is born with, so re-run `./launcher.sh --doctor` and `bash build/just/provision-check.sh .` on a fresh clone before tagging.

== CI and branch rules

`main` is protected by a ruleset with these rule types: `required_signatures`, `required_linear_history`, `non_fast_forward`, `deletion`, `code_scanning`, `code_coverage` and `copilot_code_review` (read 2026-09-30; re-read with `gh api repos/hyperpolymath/rsr-template-repo/rules/branches/main`). Only squash merges are allowed and auto-merge is on. Every commit must be SSH-signed or the PR cannot land. The workflows under `.github/workflows/` are themselves the estate's reference copies: a change here propagates to every repository minted from the template, so change the canonical reusable in `hyperpolymath/standards` first and pin to it here.

Rulesets can block a merge for reasons other than checks (review threads,
signatures, code owners): enumerate the ruleset's rule types before calling a PR
mergeable.

== Decisions

Owner rulings for the estate are recorded in `hyperpolymath/standards`
(issue #787 is the decision surface). Do not re-open a ruled question; cite it.
Rulings that bind this repository in particular: bun is the only JavaScript runtime (deno, TypeScript, ReScript, Python are banned), A2ML is retired (no `.a2ml` file may exist; descriptive and policy facts are clauses of the repo deed, `*_chora.deed`), and Justfile changes are mirrored in `.machine_readable/contractiles/Justfile`, which is kept byte-identical.
