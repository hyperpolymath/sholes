= Template damage: what rsr-template-repo shipped, why it survived, and what now stops it
:toc:
:toclevels: 3
:date: 2026-10-30

*Status*: remediation landed in this repository. Estate remediation is inventoried,
not performed — see <<Remediation>>.

== Summary

`JuliaPackageSpitter.jl` was reported as a broken Julia package: a `mise.toml`
declaring Python, Node, Go, Rust, Java, Bun and Cargo for a Julia library and no
Julia; a `Containerfile` built from two floating `:latest` stages and otherwise
consisting of TODO comments; `sholes` and a `tier` token sitting in
committed files; an SPDX gate that passed without reading a single file; a
`Justfile` whose `fmt`, `fmt-check` and `lint` recipes are `@echo` statements, so
`just quality` printed "All quality checks passed!" having run only `Pkg.test()`.

None of that was authored in that repository. It was authored here, and copied
into every repository minted while it was true. Fixing it in the downstream
repository fixes one repository; fixing it here is what stops the next mint.

== The template, and how it was found

[cols="1,3"]
|===
| Search | Result

| `gh search repos rsr-template --owner hyperpolymath --json fullName,description`
| `hyperpolymath/rsr-template-repo` — the only match. There is no separate
  Julia template repository: `rsr-julia-library-template-repo` and its variants
  return 404 (probed), so `JuliaPackageSpitter.jl` came from this template plus
  the `julia-library` archetype.

| `gh api -X GET search/code -f q='org:hyperpolymath "Juliapackage Reuse Audit"'`
| 13 files. (`gh search code` has no `--owner` flag; the `gh api search/code`
  form is the one that works.)
|===

Provenance of the specific files, from this repository's own history:

* `mise.toml` — introduced at `05fc319a`, corrected here at `cf15de59`. The
  correction reached this repository only. Repositories minted between those
  dates have the nine-runtime file, and nothing ever went back for them.
* `build/container/Containerfile` — introduced at `dbc4d67f`, corrected here at
  `adb66f51`, with the same one-way reach.
* Everything else (unfilled tokens, the `@echo` quality verbs, the vacuous SPDX
  glob) was never corrected at all — it was still true in this tree when this
  investigation started.

== The defects, and why each survived

=== 1. The SPDX gate could not fail on a non-Rust repository

`Mustfile.a2ml`'s `spdx-headers` check globbed `*.rs`, `*.res` and `*.gleam` and
capped the scan with `head -20`. In a Julia repository it matched zero files,
counted zero missing headers, and printed PASS. In a Rust repository with more
than 20 source files it graded the first 20.

*A gate that examined nothing reported coverage.* It survived because it was
green everywhere it was read.

=== 2. `container-images-pinned` asked the wrong question

The probe was `grep -q 'cgr.dev\|@sha256:' Containerfile`. Any `cgr.dev` image
satisfied it, including `FROM cgr.dev/chainguard/wolfi-base:latest`, which is
what the template shipped. The check asked "is an approved registry named" while
reporting "images are pinned".

=== 3. The mint never rendered the toolchain

`mise.toml` was copied from the spine as-is. The spine's copy was one file for
every language, so every minted repository got the union of them all. This
repository eventually repaired its own copy by hand; the archetype never carried
a Julia `mise.toml` at all, so mints kept producing the union.

=== 4. Nothing checked that `mise.toml` matched the languages present

The estate had no gate for "the toolchain this repository declares is the
toolchain its languages need". Consequently the union file was not a red build
anywhere, in any repository, for two months.

=== 5. Tokens survived because the checker skipped the files they survived in

The placeholder gate excludes `Justfile` and `*.just` (they contain just's own
`{{...}}` interpolation), and the mint's token list is a fixed set. Between the
two, `Justfile project := "sholes"`, `tier := "…"` (the `tier` brace token),
`.envrc`, `.reuse/dep5`, `Containerfile`, `devcontainer.json` and
`.devcontainer/Containerfile` kept their braces all the way into commits.

Downstream, `JuliaPackageSpitter.jl` still carries *75* unfilled
token references; the 111-repository survey below found them in 105 of 111.

=== 6. `just quality` echoed over verbs that ran nothing

The provisioning engine prints `info  fmt-check: N/A for julia (archetype:
library) — nothing to run…` and exits 0. That is honest. The `quality` recipe
then printed `All quality checks passed!`. A repo with no formatter, no linter
and no formatter-check reported "all quality checks passed".

=== 7. The archetype could not remove what the preset does not declare

The spine is polyglot on purpose, and an overlay can add files but not subtract
them. A Julia library that ships no image therefore inherited
`build/container/Containerfile` and failed `container-images-pinned` — or, before
this PR, passed it vacuously.

== What changed here

[cols="2,3"]
|===
| File | Change

| `scripts/check-spdx-headers.sh` | New. Derives the extension set from the
  languages the repository declares (via `provision-lib.sh langs`), scans every
  matched file with no cap, and fails when a declared language has no files or
  when it matched nothing at all. Names banned-language source it finds.

| `scripts/check-mise-language.sh` | New. Reads the languages and expected tools
  from the provisioning engine, then requires that every declared tool is needed
  and every needed tool is declared. Banned tools are findings wherever they
  appear. `--detect` audits repositories minted before the engine shipped with
  them.

| `scripts/check-container-pins.sh` | New. Every `FROM` must carry a 64-hex
  `@sha256:` digest or be `scratch`/a stage name. A pin behind `ARG` is a
  finding, because the digest is then decided at build time.

| `scripts/check-mint-tokens.sh` | New. Reads the answerable tokens *out of the
  mint recipe* (not a copy) and fails on any brace token that is not in it.
  Lowercase tokens included. In a minted tree with no recipe, every brace token
  is a leak.

| `scripts/render-mise.sh` | New, and now a mint step. Renders `mise.toml` from
  the detected languages plus the recipe tools. Idempotent; `--check` reports
  drift.

| `scripts/pin-container-digests.sh` | New. Rewrites `FROM` lines to digest
  pins. Refuses to run with a placeholder or malformed digest.

| `build/container/Containerfile` | **Deleted.** It had two `FROM …:latest`
  lines and a body of TODO comments — it could not build, and it failed
  `container-images-pinned` in every repository that carried it, including the
  ones that publish no image. Pinning it was not possible from here (no registry
  access) and would have left a file that still builds nothing. "Pinned or not
  at all" resolves to *not at all*: a repository that publishes an image adds
  the file and pins it. `build/container/README.adoc` and `just container-build`
  say so, and `just container-build` now explains this instead of exiting with
  "No Containerfile found".

| `scripts/prune-archetype-modules.sh` | New, and now a mint step. Deletes the
  paths an archetype's `prune.txt` lists, refusing to continue on a path that
  does not exist.

| `scripts/survey-template-damage.sh` | New. Runs these gates against real
  repositories (shallow clone each) to inventory the damage.

| `build/just/repo-init.just` | Token gate before the first write; overlay files
  recorded so only *their* `.in` names are resolved; prune step;
  `render-mise.sh`; hard gate loop before handoff.

| `archetypes/julia-library/` | `overlay/scripts/julia-quality.jl` (fmt,
  fmt-check, lint in a private tools env — Aqua and JuliaFormatter must not enter
  the package's own `[deps]`, where Aqua's own `deps_compat` check would fail
  them), the `provisioning_praxis.deed` overrides that point the verbs at it, and
  `prune.txt` removing `build/container/`.

| `archetypes/rust-cli/` | New archetype: `rust-cli_praxis.deed`,
  `Cargo.toml.in`, `src/{lib,main}.rs.in`, `tests/cli.rs.in`, `prune.txt`.

| `Justfile` | `quality` runs the verbs, fails on a non-zero exit, and fails when
  a verb reports `N/A for` every detected language. N/A is not a pass.

| `.machine_readable/contractiles/must/must.k9.ncl` | `spdx-headers` now runs the
  script instead of globbing three extensions; new `toolchain-matches-language`
  invariant.

| `.machine_readable/contractiles/trust/trust.k9.ncl` | `container-images-pinned`
  now runs the script; severity raised to `critical`.

| `scripts/validate-template.sh` | Phase 6 delegates to `check-spdx-headers.sh`;
  the dead fixed-glob implementation is removed.

| `scripts/check-no-placeholders.sh` | Fixed a silent failure: a repository with
  no `origin` remote (a fresh `git init`, exactly what a mint produces before the
  first push) made `git config` exit 1, which under `set -e` + `pipefail` killed
  the gate with exit 1 and no output.

| `.github/workflows/quality.yml` | New `mint-gates` job: the four gates plus
  both test suites. No new action — `actions/checkout` at its existing pin.

| `LICENSE` | Added — the MPL-2.0 text, identical to `LICENSES/MPL-2.0.txt`.
  There was no file named `LICENSE`, so `validate-template.sh` failed Phase 1,
  the Mustfile's `license-present` failed, and every minted repository's
  `link:LICENSE[LICENSE]` was a dead link. (REUSE keeps `LICENSES/` authoritative;
  the root copy exists because forges and readers look for it.)

| `scripts/validate-template.sh` | Two more repairs: `SCRIPT_DIR` was referenced
  but never set, so `set -u` aborted the run at Phase 6 and the last two phases
  never ran; and the required-file check demanded `CONTRIBUTING.md` in a
  repository whose `CONTRIBUTING.adoc` has been there all along.

| `.machine_readable/ai/PLACEHOLDERS.adoc` | The Project Identity section now
  separates the human name, the compiler identifier (upper and lower) and the
  forge slug, and says they are four tokens filled from four answers.
|===

Two of these controls exist because the gates themselves were written badly the
first time and the tests caught it:

* `check-spdx-headers.sh` read `git ls-files` paths relative to `--root` as if
  they were relative to the caller's directory. On a fixture that shared a path
  with the template it graded *the template's file*. Found when the Julia
  scaffold reported four files missing that plainly carried headers.
* `check-mint-tokens.sh` piped answers into `grep -q`. `grep -q` exits on its
  first match, the writer takes SIGPIPE, `pipefail` reports 141, and a *match*
  became a non-match — a different one or two tokens reported unanswerable on
  every run of an unchanged tree. Here-strings now.

== Remediation

The template is fixed here; the 111 repositories are not. Each needs a
per-repository change, and the shape of it is now mechanical:

. Copy `scripts/render-mise.sh` and `build/just/provision-lib.sh` into the repository from the same revision of `hyperpolymath/rsr-template-repo`. Older mints do not contain `scripts/render-mise.sh`, and the renderer exits with an error when `build/just/provision-lib.sh` is missing.
. Re-render the toolchain: `scripts/render-mise.sh --root .` in the repository,
   then delete the `[alias]` block (it routes `build`/`test`/`lint` to
   cargo/npm/go/ruff/prettier/black, which is how a Julia package came to have a
   `lint` that ran `ruff`).
. Pin or delete the `Containerfile`. A repository that builds no image should not
   ship one; `scripts/pin-container-digests.sh` is for the ones that do.
. Fill the tokens from `PLACEHOLDERS.adoc`, or delete the lines that need them.
   `scripts/check-mint-tokens.sh` lists every one.
. Add the SPDX headers `scripts/check-spdx-headers.sh` names.
. Replace the `@echo` `fmt`/`fmt-check`/`lint` recipes with real ones — for a
   Julia package, `archetypes/julia-library/overlay/scripts/julia-quality.jl` is
   the file to copy.

That is a migration, not a merge request, and it is deliberately not attempted
here: a template PR that also rewrites 111 repositories is a PR nobody can
review.

== What this PR does not prove

* `just repo-init` was not run end to end. The recipe needs `rustc` (its mint
  tooling is single-file Rust compiled on demand), `nickel` (the arrival pack)
  and `uuidgen`; this environment has none of the three and installing them from
  the package indexes available would have meant an installer outside the
  estate's provenance. What was verified instead: the recipe body parses as bash
  (`just --show repo-init | bash -n`), and `tests/e2e/language_profiles_mint_test.sh`
  reproduces its overlay → prune → substitute → rename → render ordering and runs
  the gates on the result. The remaining risk is in the parts of the recipe this
  test does not touch, and the CI job that runs the real mint
  (`tests/e2e/use_template_mint_test.sh`) is the place that closes it.
* The contractile probes changed here (`must.k9.ncl`, `trust.k9.ncl`) were not
  executed: they need `nickel`/`contractile`. The scripts they now call are
  tested; the plumbing from the contractile to the script is not.
* Nothing was pushed to any of the 111 repositories, and no issue was opened
  against them.
